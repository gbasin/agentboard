# Agentboard iPhone client

## Platform
ios
## Purpose and confirmed scope
An Apple-native iPhone interface with the existing Agentboard PWA's capabilities. The user requested one complete parity implementation and end-to-end validation, replacing the earlier incremental spike scope. SwiftUI provides native navigation, lists, forms, menus and sheets around xterm rendering. The iPhone is the target; m5p Simulator is the current test destination. Tailscale supplies connectivity for v1.

The catalog supports search, project/host/status filters, shared sorting and manual order. Native session creation includes directory browsing, recent paths, command presets, permission flags and remote hosts. Session management includes duplicate, rename, confirmed end, hibernate, wake and history. Library and conversation views expose saved sessions, recovery, metadata, transcripts, media, pull requests and resume controls. Settings cover shared preferences and local terminal rendering. File and photo pickers upload to the connected server and insert a quoted path without Enter.

Terminal reading and input remain central. A native keyboard proxy and one horizontally scrolling, 44-point-high quick-key row surround xterm output. The first ten controls follow PWA order: Enter, Escape, arrows, Paste, Select text, Delete word, Number keys, Tab, Shift and Control. Copy selection, Interrupt, Insert newline and Attach file follow in the same row. Compact native-glass session-overview and media-summary pills preserve terminal space, with at least 44-point-high hit targets and full summary labels through accessibility and Large Content Viewer. Only the compact chrome caps Dynamic Type at `.xxxLarge`; surrounding catalog and sheet text stays uncapped, with number-grid glyphs retaining their existing cap. Tap the terminal to type; keyboard dismissal appears only while focused. Device signing and installation remain deferred. Explicit demo mode retains sample management and the isolated raw shell fixture.
## Stack
SwiftUI navigation, lists and sheets; UIKit `TerminalInputView` for keyboard input; WKWebView for bundled xterm.js rendering and the input bridge. `BoardConnection` owns the native URLSession WebSocket, catalog, attachment, heartbeat and reconnect behavior. `SessionActions` uses a separate one-request socket for management confirmations and errors, with a timeout and no automatic replay. The connection sheet accepts the browser's base HTTP(S) URL. The socket uses `/ws?catalog=2`, including an optional proxy prefix. Tailscale setup and authentication onboarding are not implemented in the app.
## Lifecycle contract
Suspend the socket in the background. Reconnect and restore the selected session in the foreground. Only accept input after terminal readiness; never replay disconnected input. Open a fresh socket for each selection to isolate stale responses, including a later visit to the same session ID.
